# Формат APC-маркера shell-интеграции не объединяется в общую схему кодирования/разбора

Решение (кандидат №6 из архитектурного ревью `/improve-codebase-architecture`, 2026-07-17, отклонён при `/codebase-design` grilling 2026-07-18): раскладка полей маркера (`user·host·pwd·euid·exit·sudoUser`, разделитель `\x1f`) остаётся продублированной в трёх местах — строке настройки `SHELL_INTEGRATION_SETUP` (`src/main/ssh/shellIntegration.ts`), разборе `parseMarker` там же, и тестовом хелпере `mk()` (`shellIntegration.test.ts`) — без единой декларации, из которой генерировались бы все три.

**Почему это не просто отложенная уборка, а сознательный отказ.** Исходное ревью помечало кандидата как Speculative — «выгода проявится только при следующем изменении протокола». К моменту grilling это изменение уже произошло: маркер расширили с 5 до 6 полей (добавили `SUDO_USER` для различения `sudo`-рута от настоящего root-логина). Риск, ради которого предлагалось объединение (забыли обновить одно из трёх мест при изменении формата), не подтвердился — все три места обновлены согласованно, включая явно написанный и покрытый тестом путь обратной совместимости со старым 5-полевым форматом (`shellIntegration.test.ts`, тест «маркер старого формата»).

**Дополнительная причина.** То, что в отчёте называлось «encoder», не является рантайм-логикой в нашем процессе — `SHELL_INTEGRATION_SETUP` статическая printf-строка, которую значениями подставляет удалённый shell, а не наш TypeScript. Объединить можно было бы только список полей (имена/порядок), не пару функций кодирования/декодирования в привычном смысле — и даже это принесло бы пользу только для основного (текущего) формата: ветку обратной совместимости со старым форматом всё равно пришлось бы писать отдельно вручную, не выводя из общей схемы.

**Когда пересматривать.** Если при будущем изменении формата маркера (седьмое поле, смена разделителя и т.п.) обнаружится реальный баг рассинхрона между тремя местами — стоит вернуться к этому решению с новой, на этот раз подтверждённой на практике причиной.

Решение принято 2026-07-18.
