# Jump-хост: отдельное SSH-соединение с bastion на каждую сессию, без пула

Решение (сессия `/grill-with-docs` по фидбоку «не хватило поддержки jump-хоста», 2026-07-31): если несколько целевых хостов (или несколько сессий одного хоста) используют один и тот же bastion, каждая сессия открывает **своё собственное** TCP/SSH-соединение до bastion и свой `forwardOut`-туннель через него. Общий пул/мультиплексирование соединений с bastion (по аналогии с `ControlMaster` в OpenSSH) не реализуется.

Причины:
- Архитектура `sessionManager.ts` уже устроена так, что каждая `ManagedSession` независима — свой `client: Client`, свой жизненный цикл подключения/reconnect (SSH-06)/disconnect. Пул потребовал бы отдельного shared-состояния "соединение с этим bastion", подсчёта ссылок (когда закрывать соединение с bastion — когда закрылась последняя ссылающаяся на него сессия?) и своей обработки ошибок, независимой от ошибок конкретной сессии.
- SSH-соединение — недорогая операция; параллельные независимые логины на один bastion — нормальная практика, не являются проблемой производительности для аудитории 1.0.
- Auto-reconnect (SSH-06) остаётся простым: сессия, потерявшая связь, просто переустанавливает оба хопа заново, не завися от состояния других сессий, использующих тот же bastion.

**Рассмотренная альтернатива:** один общий Client-коннекшен на bastion, шаренный между всеми сессиями, которые через него идут (мультиплексирование каналов через один логин, как делает `ssh -M`/`ControlMaster`). Отклонена — сложнее в реализации и отладке, а выигрыш (экономия на одном лишнем TCP/SSH-хендшейке на сессию) не оправдан для целевой аудитории.

**Известный компромисс:** если у bastion в реальной среде есть жёсткий лимит на число одновременных соединений с одного клиента, несколько параллельных сессий через него могут упереться в этот лимit раньше, чем при мультиплексировании. Такие жёстко зарегулированные корпоративные среды — ниша за пределами аудитории 1.0 (см. `Development_Roadmap.md` §3.14, та же логика, что и по прокси).

Решение принято 2026-07-31.
