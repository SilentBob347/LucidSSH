# 1. Введение

## 1.1 Цель документа

Документ определяет функциональные и нефункциональные требования к LucidSSH for Windows — настольному SSH-клиенту для Windows, ориентированному на новичков, но пригодному и для опытных пользователей. Документ является основой для проектирования, разработки и приёмочного тестирования.

## 1.2 Контекст продукта

Существующие SSH-клиенты делятся на две группы: минималистичные инструменты без объяснений (PuTTY, OpenSSH) и профессиональные комбайны с избыточными функциями и подписками (Termius, MobaXterm). Новичок, подключающийся к VPS или домашнему серверу, оказывается без ориентиров: он не понимает ошибки соединения, не знает, что делает команда, и рискует необратимо повредить сервер.

LucidSSH заполняет этот пробел: полноценный SSH-клиент с активной защитой от деструктивных действий и встроенными обучающими подсказками — без подписки, аккаунта и облака.

## 1.3 Целевые группы пользователей

| Группа | Описание | Ключевые потребности |
|---|---|---|
| Новичок | Первое подключение к VPS, NAS или Raspberry Pi. Не знает терминологию SSH. | Понятные ошибки, защита от опасных команд, объяснение что происходит |
| Домашняя лаборатория | Несколько серверов, периодическая работа, не сисадмин. | Удобный менеджер хостов, история, дашборд сервера |
| Разработчик | Несколько SSH-подключений в работе, привык к терминалу. | Быстрые подключения, вкладки, сниппеты, не мешай |
| Мигрант с PuTTY | Привык к PuTTY, хочет вкладки и современный UI. | Импорт сессий PuTTY, привычная надёжность |

## 3.4 Страж опасных команд

> **Примечание:** ключевое конкурентное преимущество. Страж — средство предупреждения о **распознанных** опасных командах, а не гарантия блокировки любой разрушительной операции. Это ограничение отражается в интерфейсе и документации.

| ID | Требование | Приоритет | Зависимость | Критерий приёмки |
|---|---|---|---|---|
| ✅ GUARD-01 | Встроенный список опасных паттернов (rm -rf, dd, mkfs, chmod -R 777, truncate, >/dev/sda и др.) в отдельном файле `src/main/guard/patterns.ts`, покрыт тестами. Обновляется вместе с приложением. | Must | — | Все команды из контрольного списка перехватываются. |
| ✅ GUARD-02 | При вводе опасной команды и нажатии Enter приложение перехватывает её **в main process до отправки на сервер** и показывает модальное окно с: (а) объяснением что произойдёт на русском, (б) масштабом последствий, (в) полем подтверждения (ввод имени объекта или слова ПОДТВЕРЖДАЮ). | Must | GUARD-01 | rm -rf /var/www не выполняется без ввода подтверждения. |
| ✅ GUARD-03 | Предупреждение содержит конкретную затронутую цель с реальным путём из команды, а не общую фразу. | Must | GUARD-02 | Текст предупреждения содержит реальный путь из команды. |
| ✅ GUARD-04 | Страж проверяет команды из всех источников: ручной ввод, clipboard, история, каталог команд, breadcrumb, будущие сниппеты. | Must | GUARD-01 | Опасная команда из истории и из каталога так же перехватывается. |
| ✅ GUARD-05 | Опытный пользователь может отключить страж для конкретного хоста или глобально. | Must | GUARD-01 | После отключения команды выполняются без модального окна. |
| ✅ GUARD-06 | Все перехваченные команды логируются в историю с отметкой «заблокировано» или «подтверждено». | Should | GUARD-01 | История содержит записи с корректным статусом. |

# 5. Требования к UX и интерфейсу

## 5.1 Принципы интерфейса

- **Не мешай опытному пользователю.** Все обучающие подсказки появляются не более 3 раз, затем скрываются. Глобальный переключатель «Режим эксперта» отключает все подсказки.
- **Локальность прежде всего.** Всё, что может работать без интернета — работает без интернета. Единственные внешние соединения: SSH к серверам пользователя и HTTPS к источнику обновлений.
- **Понятные ошибки.** Ни одна SSH-ошибка или ошибка команды не остаётся без объяснения на русском.
- **Визуальный контекст.** Пользователь всегда видит: к какому серверу подключён, кем является, где находится, здоров ли сервер.
- **Честность интерфейса.** Защитные механизмы не обещают абсолютной гарантии. Страж описывается как предупреждение о распознанных опасных командах.
- **Честность в неопределённости.** Если приложение не может определить причину, последствие или контекст со стопроцентной точностью, оно явно показывает степень уверенности вместо того, чтобы выдавать предположение за факт.

## 5.2 Обязательные UI-компоненты

Диалог создания нового хоста содержит подсказки для каждого поля:

# 9. Требования к обновлению и подписи

> Полная стратегия — в `Release_and_Update_Strategy.md`. Здесь — требования с критериями приёмки.

| ID | Требование | Приоритет | Критерий приёмки |
|---|---|---|---|
| ✅ UPD-01 | Приложение проверяет GitHub Releases при запуске и по ручной команде, не блокируя интерфейс и SSH. | Must | При новой стабильной версии показывается её номер и изменения; без интернета приложение продолжает работу без навязчивой ошибки. |
| ✅ UPD-02 | Загрузка и перезапуск — только после понятного действия пользователя. | Must | Приложение не закрывает активную SSH-сессию без подтверждения. |
| ✅ UPD-03 | Перед установкой проверяется целостность пакета через сравнение SHA-256 с контрольной суммой, опубликованной в GitHub Release. | Must | Повреждённый или не совпадающий по контрольной сумме пакет отклоняется и не устанавливается. |
| ✅ UPD-04 | Обновление не удаляет пользовательские данные и секреты. Перед необратимой миграцией БД создаётся локальная резервная копия. | Must | После обновления с предыдущей версии доступны прежние хосты, история, настройки и записи Credential Manager. |
| ✅ UPD-05 | Каждой версии соответствует уникальный номер, Git-тег и GitHub Release; все файлы обновления из одной сборки. | Must | Установленная предыдущая версия обнаруживает релиз и обновляется. |
| ✅ UPD-06 | Предыдущие стабильные версии сохраняются в GitHub Releases. | Should | Пользователь может вручную скачать предыдущий установщик, если релиз не отозван по безопасности. |
| ✅ SIGN-01 | Стабильный установщик и пакет обновления подписываются доверенным Code Signing Certificate с меткой времени. *(Не применимо для версии 1.0 — релиз выходит без сертификата подписи.)* | — | Свойства файла Windows показывают действительную подпись и ожидаемого издателя. |
| ✅ SIGN-02 | Закрытый ключ сертификата не хранится в репозитории или исходном коде. *(Не применимо для версии 1.0 — релиз без сертификата.)* | — | Аудит репозитория и релизных файлов не обнаруживает сертификат с закрытым ключом, пароль или токен доступа. |
